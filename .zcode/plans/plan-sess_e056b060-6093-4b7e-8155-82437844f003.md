# AI 终端代理（Agent 模式）· 需求范围与实施规划

## 已确认的产品决策
- **默认审批模式**：白名单自动（只读命令自动执行，写操作每步弹窗确认，高危命令拦截）
- **v1 终端范围**：全部类型（本地 bash/zsh 用 OSC9 提示符信号；SSH/PowerShell/cmd 用屏幕稳定启发式）
- **PROD 主机**：仅允许"每步手动确认"模式，白名单/全自动被禁用

## 核心循环（每个代理一次一个目标）
```
输入目标 -> [思考:调模型出 JSON 动作] -> [安全门: 分类+审批]
  -> [执行: write + \r] -> [等待完成: prompt_seq 信号 / 屏幕稳定 / 超时]
  -> [观察: visible_text] -> 回到思考 -> 模型返回 done / 达到步数上限 / 用户停止
```

## Phase 1 - 命令完成检测基建（src/terminal/mod.rs）
- `TerminalInstance` 加 `pub prompt_seq: u64`：在 poll_cwd 的 OSC "9;" 解析分支（mod.rs:524 附近，cwd 变更 if 之外）每解析到一条完整序列就 +1。bash/zsh 的 PROMPT_COMMAND/precmd 每次提示符都发 OSC9（mod.rs:99-118），即"计数增长 = 新提示符 = 上一命令结束"
- 代理读屏前先 `set_dirty()` + `sync()` 刷新缓存（visible_text 目前读 last_content 缓存）
- 纯函数测试：序列解析计数的可测部分

## Phase 2 - 安全层 + 动作协议（新模块 src/app/agent.rs）
- **命令分类器**（纯函数）：首个词 + 参数分析 -> `Safe`（ls/cat/grep/ps/df/git status 等只读）/ `Risky`（rm/mv/dd/sudo/kill/shutdown/重定向/管道写入等）/ `Destructive`（rm -rf、dd of=、mkfs、fork 炸弹、`:(){` 模式等，永不自动执行）
- **审批模式枚举** `Manual | Allowlist | FullAuto`（默认 Allowlist）：矩阵决定 每类命令在每模式下 = 自动 / 确认 / 拒绝；PROD 终端强制降级为 Manual
- **动作协议**：模型回复严格 JSON `{"action":"run"|"done"|"say","command":"...","reason":"..."}`，serde_json 解析（先例 updater.rs:286）；解析失败回退提取 markdown 围栏中的命令行
- 单元测试：分类器全类别、JSON 解析（合法/非法/围栏回退）、审批矩阵

## Phase 3 - 状态机与 UI（src/app/agent.rs + ai_ui.rs）
- `AgentState`：目标、步数、每步 transcript（命令/结果摘要/状态）、phase 枚举、目标 tab、独立 mpsc 通道与 busy 标志（与 ai_busy 分离，代理激活时禁用手动发送）
- tick 挂在 update() 顶部：PTY 输出天然驱动重绘帧；等待态用 `request_repaint_after`（view.rs:556 模式）保证空闲不饿死；屏幕稳定判定用绝对时间（last_sample 模式，app.rs:3996）
- 完成检测策略：有 OSC9 能力（本地 bash/zsh）等 prompt_seq 增长；否则等屏幕文本稳定 ~600ms；均带 30s 超时 -> 弹"手动继续/停止"选择；交互式程序（vim 等）用户可手动接管
- UI：AI 面板加"代理"模式区（目标输入、审批模式选择、启动/停止按钮、分步 transcript），运行中终端 tab 标题加机器人图标；停止 = 按钮 + 可配置全局快捷键（默认 Ctrl+Shift+.，按 default_key_binds + shortcut_hint_ids + shortcut_label_for 三处登记，在 any_modal_open 仲裁**之前**消费；不用 Esc--已被十余处占用）；旧 settings.json 补默认键迁移
- 确认弹窗复用 dialog_keys + any_modal_open + dialog_button_row 协议；弹窗打开期间代理 tick 不推进

## Phase 4 - 设置 + i18n
- AppSettings 新增：`agent_approval_mode`（默认 allowlist）、`agent_max_steps`（默认 10）；设置页 AI 组内加代理子组（serde default 函数先例 app.rs:86-92）
- i18n 约 25 个新 key × 9 语言（代理面板/分步状态/审批弹窗/停止快捷键标签等），键一致性测试必须过

## Phase 5 - 测试 + 门禁 + 交付
- 新增测试约 10 个（分类器、协议解析、审批矩阵、状态迁移、稳定判定的纯函数部分）
- cargo check / clippy -D warnings / fmt / test 全绿；更新 project.md（功能状态 + Roadmap）；完成后等用户确认再 commit（不 push）

## 明确不做（v1）
多代理并行、后台无人值守/定时运行（必须在应用活跃时运行）、退出码 OSC 扩展上报（v2）、跨终端多 tab 编排、代理写入选中已有文本的交互式程序。

## 风险与对策
- 误判命令完成（长命令如 find /）：30s 超时 + 手动继续兜底；transcript 全程可审计
- 屏幕稳定启发式误触发（有周期性输出的程序，如 top）：检测周期输出特征 -> 提示切换手动模式
- 代理与广播输入串扰：代理运行中在该终端上暂停广播复制并 toast 提示
- 模型返回非 JSON：围栏回退 + 最多 2 次重试后转"手动模式"继续
