# OpenNex 跨平台视觉主题设计

## 目标

为 Windows、macOS 和 Linux 提供同一套可导入、导出和持久化的视觉主题格式。主题覆盖 OpenNex 自身界面和标准终端 ANSI 渲染，不修改 Shell 配置，也不尝试从终端字符中推断命令、路径、字符串或文件类型。

## 范围

第一版开放以下配置：

- 应用颜色：背景、侧栏、面板、输入框、边框、文本、弱文本、悬停、激活、选中、强调、警告、危险、锁定遮罩和窗口阴影。
- 终端颜色：前景、背景、ANSI 普通 8 色、明亮 8 色、暗淡色、光标、选区和链接。
- 字体：终端字体候选列表、终端字号、单元格间距和指令菜单字号。
- 元数据：格式版本、主题 ID、名称、作者和来源。

第一版明确排除：

- 语言、快捷键、历史上限、回滚行数、默认 Shell、工作区和窗口状态。
- 锁定密码、命令历史、本机路径等隐私或设备相关数据。
- Shell Prompt 注入、`LS_COLORS`、PSReadLine 和语法高亮配置。
- 按字符语义设置颜色或局部字号。

## 配置边界

主题正文使用 `.opennex-theme.json` 文件。`settings.json` 只保留行为设置、当前主题 ID，以及导入时是否应用字体和尺寸的偏好。主题导入不会覆盖非视觉设置。

内置主题存放于 `assets/themes/` 并通过 `include_str!` 嵌入程序。首次启动使用内嵌默认主题；用户主题存放在平台数据目录的 `themes/` 子目录。内置主题只读，编辑后必须另存为用户主题。

## 数据模型

主题顶层包含：

- `format_version`: 第一版固定为 `1`。
- `id`: 稳定、文件安全的标识符。
- `name`、`author`: 展示元数据。
- `app`: OpenNex 界面色板。
- `terminal`: ANSI 色板和终端专用颜色。
- `typography`: 字体候选列表和尺寸。

所有颜色使用严格的 `#RRGGBB` 或 `#RRGGBBAA` 格式。字号和间距在加载时限制到产品支持范围。未知字段允许忽略，以支持同一主版本内向前兼容；未知 `format_version` 拒绝导入并保持当前主题不变。

## 跨平台策略

应用颜色和终端 ANSI 色由 egui/egui_term 渲染，因此三平台使用同一配置值。字体使用有序候选列表：选择首个已安装字体，均不可用时回退到 `monospace` 和 OpenNex 内嵌字体。尺寸使用 egui 逻辑像素，交由平台 DPI 缩放处理。

导入和导出通过 `rfd` 原生文件对话框完成。文件内容不包含平台绝对路径，因此可以直接跨平台复制。

## 应用流程

1. 启动时读取 `settings.json` 中的主题 ID。
2. 先在用户主题目录查找，再查找内置主题；失败时回退内置默认主题。
3. 校验主题并解析成运行时颜色对象。
4. 同一主题对象同时传给应用界面和所有终端视图。
5. 设置页编辑副本并实时预览；关闭或取消时恢复已保存主题；应用时原子写入用户主题并更新设置。
6. 导入先读取、解析、校验和处理 ID 冲突，全部成功后才写入用户目录。

## 错误处理

- 无效 JSON、版本、颜色、尺寸或空字体列表均返回面向用户的具体错误。
- 导入失败不改变当前主题，也不留下部分文件。
- 保存先在同目录写入并同步临时文件；替换已有文件前保留备份，失败时恢复备份，降低崩溃或平台替换语义差异造成文件损坏的风险。
- 当前主题丢失或损坏时记录日志并回退默认主题。
- 导入同 ID 主题时生成新的用户主题 ID，不覆盖已有主题。

## UI

“外观”设置页改为主题选择器、实时预览、应用颜色编辑、终端色板编辑、字体设置和导入/导出操作。颜色字段按语义分组，终端 16 色使用紧凑色板网格。第一版不引入独立主题商城或在线下载。

## 测试

- 单元测试覆盖格式解析、版本检查、颜色校验、范围校验、内置主题唯一性、字体回退、导入冲突和原子保存。
- egui_term 单元测试覆盖选区、光标和链接颜色的主题映射。
- AppSettings 迁移测试确保旧版 `theme`、`terminal_theme`、前景色和背景色可以映射到新主题选择，且不丢失非主题设置。
- 最终运行格式检查、库测试、完整测试和 debug/release 编译。

## 成功标准

- 同一个主题文件可在 Windows、macOS 和 Linux 导入。
- 应用界面及 ANSI 终端色在三个平台保持相同配置语义。
- 字体不存在时可靠回退，主题仍能加载。
- 导入主题不会修改快捷键、语言、历史、密码或工作区。
- 无效主题不会破坏当前配置。
